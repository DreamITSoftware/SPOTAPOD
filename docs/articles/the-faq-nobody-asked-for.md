# The FAQ Nobody Asked For: Answering Every Objection to This Project

### The format experiment of pre-empting criticism instead of waiting for it in the comments

Most research projects respond to objections reactively, in comments or follow-up posts, after a critic raises them. This piece tries the opposite: stating the strongest objections to this project's own methodology, unprompted, before anyone else does.

## "Isn't this just three cherry-picked datasets?"

Fair concern. These are three specific engagement-pod tool exports, not a random or comprehensive sample of all pod activity or all LinkedIn content. This project has never claimed its findings generalize to "LinkedIn as a whole" beyond what's directly measurable in these three sources, and every article in this series is explicit about which specific dataset a claim comes from.

## "How do we know the raw data itself is accurate?"

We don't, fully. This project's VERIFIED tier means "independently recomputed from the source file as supplied," not "confirmed accurate against LinkedIn's own internal systems," which this project has no access to. That's a real, acknowledged limitation, documented in this project's own limitations.md.

## "Isn't 'engagement pod' just normal networking behavior?"

There's a real gray area between mutual, voluntary support among a small professional network and a paid, automated, large-scale reciprocal-engagement service. This project's datasets describe services explicitly built and marketed as the latter, automated, paid, scaled, not the former, but the boundary case is real and this project doesn't claim otherwise.

## "Why hide the raw data if you're trying to inform the public?"

Because a raw record can re-identify a real person even after removing an obvious name field, and the public-interest value of this research comes from the aggregate patterns, not from any specific individual's post. This trade-off is explained at length in this project's privacy.md, and it's a deliberate choice, not an oversight.

## What this is, and isn't

**A transparency exercise, not a new finding.** Every objection here is presented as a genuine, unresolved limitation where one exists, not deflected.

Full limitations documentation: **github.com/DreamITSoftware/SPOTAPOD**.
